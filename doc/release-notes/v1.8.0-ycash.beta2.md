`koganyd` v1.8.0-ycash.beta2: Kogany, the Ycash node on Zakura, with the vault network upgrade and
the Ycash Yellowback (YED) rule module.

**Pre-release.** kogany is not a qualified Ycash node line yet (kogany plan K-19). Run it on the
Ycash testnets only; expect resyncs and breaking changes between pre-releases. No activation height
for the vault upgrade is set on mainnet.

**Changes since beta1**

- **Ycash's block time bounds (consensus fix).** A block's time may be at most 10,800 s past the
  median time of the previous 11 blocks and at most 14,400 s past the node's clock, as ycashd
  enforces (twice Zcash's bounds). beta1 carried Zcash's 5,400 s and 7,200 s and rejected valid Ycash
  blocks: fast-testnet block 510,256, and 51 mainnet blocks from height 974,995 on, so it could not
  follow either chain past them. beta2 follows the fast testnet through the Vault activation at 510,400
  with ycashd's block hashes, and validates mainnet from the Canopy checkpoint (1,100,006) to 3,097,335
  with ycashd's tip and value pools. The median-time rule's reject reason is ycashd's
  `time-too-far-ahead-of-mtp`.
- **`z_validateaddress` answers for post-quantum addresses** as ycashd does: `isvalid` true, `type`
  `pq`, the scheme, its name and the key hash (no wallet field `ismine`). YED-form and other-network
  addresses stay invalid.
- **Post-quantum addresses show their scheme (D-9), `rpcversion` 9.** A post-quantum address names
  its signature scheme in its third character: `sqf…`/`sqs…` (FN-DSA-512 / SLH-DSA) for YEC and
  `ybf…`/`ybs…` for YED on mainnet, `tqf`/`tqs`/`ytf`/`yts` on testnet, `rqf`/`rqs`/`yrf`/`yrs` on
  regtest; still 53 characters. Every RPC prints and takes only this form; the earlier form is an
  invalid address (-5). `yed_getinfo.rpcversion` is 9, and `params.pqAddressVersion` and
  `params.pq.plainAddressVersion` are objects keyed by scheme number. The address index on disk is
  unchanged: no resync is needed.
- **`validateaddress` names the scheme.** For a post-quantum address it answers `pqscheme`,
  `pqschemename` and `pqkeyhash`, as ycashd does.
- **Testnet profiles.** `network = "Testnet"` is testnet-yb-fast. `network = "TestnetSlow"` and
  `network = "TestnetLegacy"` select the two shadow forks of mainnet. `--help` and the generated
  config name them. The fast testnet is checkpointed through block 510253.
- **Release name in the user agent.** The P2P user agent is `/koganyd:1.8.0-ycash.beta2/`.
- **`getinfo` errors.** The "chain tip metrics channel closed" warning no longer shows in `getinfo`
  `errors` when the health server is not configured. It is logged at debug level.
- **A local ycashd as a peer.** A loopback or private address you name (`initial_mainnet_peers`,
  `initial_testnet_peers`, `addnode`, the peer cache) is dialled on any port, so a ycashd on
  `127.0.0.1:18233` can be a peer. Routable addresses keep the port rule.
- **Non-routable peers are never gossiped.** A `getaddr` answer no longer contains loopback or
  private addresses, as on ycashd. Before, a private peer on a Ycash port was handed out.
- **Address-index RPCs and other networks.** `getaddressbalance`, `getaddresstxids`,
  `getaddressutxos`, `getaddressdeltas` and `getaddressmempool` answer `-5 "Invalid address"` for an
  address of another network, as ycashd does. One such address fails the whole call.
- **Smaller Linux downloads.** The Linux binary no longer carries its debug info. It ships as a
  separate `koganyd_<tag>_<platform>.debug.tar.gz`, listed in `SHA256SUMS`. Put `koganyd.debug`
  beside `koganyd` to get file and line numbers in backtraces; function names are there without it.
- **Mainnet restore guide.** `doc/mainnet-restore.md` restores a mainnet node from a signed snapshot
  bundle instead of syncing from genesis. Its step that moves old state aside runs only when koganyd
  is stopped and the state format matches, and it moves only mainnet state, never deletes it.
- **Mixed-shape tests.** Transactions with Sapling spends and outputs beside post-quantum and vault
  scripts (a second recorded chain adds FN-DSA-512 beside a Sapling spend and a vault unlock beside
  Sapling), recorded on a C++ node and replayed, are accepted the same way, and malformed variants
  are refused with ycash6's text at the same stage. These tests changed no consensus code.
- **Where koganyd answers differently from ycashd** is now listed in `docs/kogany.md` (below).
- **yewd and YEW fixes (yew `fc56fba7`).** A post-quantum `z_sendmany` through yewd whose fee is within
  the post-quantum fee cap is no longer refused as `absurdly-high-fee` (yew #40). yewd refuses a raw
  spend of an unconfirmed output that a pending transaction gives YED, as ycashd does, so that YED
  cannot burn (yew #42). A seed restore finds every coin within the key lookahead, also keys paid out
  of order, and `restore_in_progress` stays true until the node has synced (yew #41). The YEW app and
  web wallet show post-quantum YEC balances and send from post-quantum addresses without the
  Yellowback service (yew #38).

**What works**

- Following Ycash mainnet, the three Ycash testnets and regtest.
- The vault primitive and the Yellowback module, as ycash6 enforces them.
- The stock Ycash RPCs, the vault `set_*` / `vault_*` RPCs and the `yed_*` RPCs, `rpcversion` 9.
- yewd (the YEW core as a daemon, in the yew repository) as the wallet in front of koganyd: sends
  between every address type, vault locks, mints, YED sends and redeems were run end to end on
  regtest with koganyd as yewd's node and as the miner.

**What does not yet, and known differences**

- No wallet in the node. `yewd` is the wallet sidecar; it has no release in this wave: build it from
  yew `fc56fba7` (Getting started, below).
- **Where yewd differs from ycashd's wallet:**
  - Not served: `importaddress` and the other watch-only and viewing-key imports, the unified-account
    RPCs, `getunconfirmedbalance`, and `z_mergetoaddress` from post-quantum addresses (use
    `z_sendmany`, which sends between every address type).
  - A yewd recovery phrase and a ycashd one derive different transparent keys (yewd
    `m/44'/347'/0'`), so moving a wallet between them by phrase does not bring its transparent coins:
    send them instead.
  - On koganyd, a seed restore against a stalled or parked chain (an old tip) keeps
    `restore_in_progress` true; the wallet stays usable.
  - `getbalance` leaves out the 0.0001 YEC each held YED token carries (`getwalletinfo` counts it).
    YED outputs are kept out of coin selection rather than locked, so `listlockunspent` does not
    list them and `yed_unlockcoin` releases nothing.
  - `gettransaction` `details` leave out the change of a vault funded from an external key.
  - The default funding of a vault lock leaves one coin locked after the lock is
    accepted.
  - A vault lock funded only from coinbase that must be shielded is not refused by yewd up front; where
    coinbase must be shielded, the node rejects it.
  - `createrawtransaction` orders its outputs by address, not as given.
  - Sends with no post-quantum party pay the ZIP-317 fee; ycashd's wallet pays a flat 1,000 zat.
- No YED attestor set on any public network, so YED cannot be minted on the fast testnet.
- **A miner must quote the price.** Where Yellowback is live, send `yed_setquote <priceMicroUsd>
  <sourceMask>` to koganyd and renew it as the price moves; blocks mined without a quote leave the
  price window empty and every mint fails with `mintpol-no-price: no defined price at the reference
  height` (README, "Mining: quote the price").
- **`getaddressbalance` has no `txcount`.** koganyd answers `balance` and `received` only; ycash6
  adds `txcount`. Planned after beta2.
- **Wrong argument counts answer `-1`.** A call to koganyd with too few or too many arguments answers
  `-1` "Invalid params"; ycashd answers `-32602` with the method's help. yewd answers ycashd's
  `-32602` for every method it forwards to koganyd; clients that call koganyd directly see `-1`.
- No wallet fields (`ismine`, `iswatchonly`, the wallet half of `getinfo`, `protectedByIndex`), and
  some node fields differ from ycashd's (`docs/kogany.md`, "Where a koganyd answers differently from
  ycashd").
- No testnet peers are built in: name a seed in `initial_testnet_peers`, for example
  `fastnet-seed.ycash.team:18833` (the seeds run ycashd 6.22.0-beta2).
- **Ban score for the median-time rules.** ycashd checks difficulty before time and scores the
  median-time rules 0; koganyd checks time first and scores them 100. Both reject the same blocks.
- No Windows or Intel macOS build. Linux builds need glibc 2.39 (Ubuntu 24.04 or newer).

**Getting started**

The cosign identity is that of the tag-push run of `kogany-release.yml` that built these assets; a
rebuild means a new tag. `gh attestation verify` checks the build provenance of a package, an SBOM or
`SHA256SUMS`.

```sh
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob --bundle SHA256SUMS.cosign.bundle \
  --certificate-identity https://github.com/boyfromcave/kogany/.github/workflows/kogany-release.yml@refs/tags/v1.8.0-ycash.beta2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
gh attestation verify koganyd_v1.8.0-ycash.beta2_linux-x86_64.tar.gz -R boyfromcave/kogany
tar xzf koganyd_v1.8.0-ycash.beta2_linux-x86_64.tar.gz && cd koganyd_v1.8.0-ycash.beta2_linux-x86_64
printf '[network]\nnetwork = "Testnet"\nlisten_addr = "[::]"\ninitial_testnet_peers = ["fastnet-seed.ycash.team:18833"]\n\n[rpc]\nlisten_addr = "127.0.0.1:18832"\n' > testnet.toml
./koganyd -c testnet.toml start
```

yewd, the wallet in front of koganyd, is built from source at yew `fc56fba7` (Rust 1.92, pinned by the
repository):

```sh
git clone https://github.com/boyfromcave/yew && cd yew && git checkout fc56fba7
cargo build --release --locked --manifest-path yewd/Cargo.toml   # yewd/target/release/{yewd,yewd-signer}
```

Run it on another RPC port than koganyd's, with `-backendrpcport` set to koganyd's RPC port and
`-backendrpccookiefile` to koganyd's cookie; yewd's README has the options.

Ports: mainnet 8833 / RPC 8832; testnet `fast` 18833 / 18832; `slow` 18933 / 18932. Each tarball's
`README.txt` has the details; the [kogany README](https://github.com/boyfromcave/kogany#readme) has
the rest.
