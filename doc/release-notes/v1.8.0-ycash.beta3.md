`koganyd` v1.8.0-ycash.beta3: Kogany, the Ycash node on Zakura, with the vault network upgrade and
the Ycash Yellowback (YED) rule module.

**Pre-release.** kogany is not a qualified Ycash node line yet (kogany plan K-19). Run it on the
Ycash testnets only; expect resyncs and breaking changes between pre-releases. No activation height
for the vault upgrade is set on mainnet.

**What you must do when upgrading from beta2**

- **Allow for a database upgrade at the first start.** The state moves from format 30.2.0 to
  30.3.0 (the transparent pools by type and the chain transaction count, below), once, before the
  node serves RPC or commits a block. It takes about a minute or two on mainnet and less on the
  fast testnet, logs its progress every 100,000 heights, and continues where it stopped if the
  start is interrupted. Give health checks and supervisors that time. The step is one-way: no
  version takes the database back to 30.2.0, but a beta2 `koganyd` still opens it, and the next
  beta3 start fills in what the older binary added.
- **Fast testnet: upgrade before the development fund's mandate ends there.** The fast testnet's
  mandate now ends at height `<HEIGHT, set at the release-candidate cut>`. From that height a
  block without the fund output is valid; a node on beta2 or older rejects it and leaves the chain.
  Mainnet, the slow and legacy profiles and regtest are unchanged.
- **Miners: the fund donation is now opt-in.** `mining.ydf` (ycashd's `-ydf`) defaults to 0: once
  the mandate has ended, a block this node builds pays the miner the whole subsidy and every fee.
  To keep donating, set `ydf = 5` under `[mining]`. Before the mandate ends the 5 % output is a
  consensus rule and is paid whatever the setting says.
- **Clients: `rpcversion` is 10** (`yed_getinfo`); it was 9.

**Changes since beta2**

- **`getcoinbasetemplatefor`**, ycashd's new call, to the same contract: a pool keeps the stock
  `getblocktemplate` reply and asks for the coinbase that pays one miner, naming the template by its
  previous block hash and transaction ids. The node derives the amount (the subsidy, less the fund
  output its own coinbase carries, plus the named transactions' fees); there is no amount argument.
  The payout address is transparent, post-quantum (from the Vault upgrade on) or Sapling.
- **Sapling coinbase.** A coinbase can pay a Sapling address, through `getcoinbasetemplatefor` or a
  Sapling `mining.miner_address` (ycashd's `-mineraddress=<Sapling>`). This needs ycashd's
  `sapling-output.params` (3,592,860 bytes), read once at start from `mining.sapling_output_params`
  or from ycashd's parameter directory (`~/.zcash-params`; on macOS
  `~/Library/Application Support/ZcashParams`) and checked by its SHA-256. It is in the
  `zcash-params-v1` release of the ycash-infra repository and is what ycashd's `fetch-params`
  installs. Without it a Sapling coinbase is refused with "Sapling output parameters are not
  loaded"; transparent and post-quantum coinbases work as before.
- **`transparentPools` and `transactions`.** `getblockchaininfo` and `getblock` (verbosity 1 and 2,
  there with the change in the block) answer the transparent value pool split by address type
  (`transparent_ecc`, `transparent_pq`, `pq_channel`, `vault`, `vault_intent`, with `pq_by_scheme`
  and `vault_by_module`), and `getblockchaininfo` answers `transactions`, the number of transactions
  in the best chain, as ycashd does. Find entries by `id`, not by position. Where the node does not
  know a figure it says so: an entry with `monitored: false` and no amounts, and no `transactions`
  key. A pruned node that upgrades a beta2 database gets `transactions` but not the pools (the
  blocks they are computed from are gone). These are node-side indexes, not consensus rules.
- **Address index answers as ycashd's.** `getaddressbalance` answers `txcount`,
  `getaddressfirstlastheight` is served, and `getblockchaininfo.commitments` is the size of the
  Sprout tree at the tip (it was always 0).
- **Insight explorer fields, opt-in.** `[rpc] insight_explorer = true` is kogany's counterpart of
  ycashd's `-insightexplorer` for transactions and blocks: on an archive node it adds `value`,
  `valueSat` and `address` to each non-coinbase input in `getrawtransaction <txid> 1` and
  `getblock <hash> 2`, and `blockfee` to `getblock` at verbosity 1 and 2. It is off by default; keep
  it off where untrusted clients reach the RPC port. kogany has no spent index: a call whose inputs
  have more than 5,000 distinct parent transactions answers without the input fields and logs it
  (ycashd has no cap), and `blockfee` is absent, never 0, where it is not known.
- **JSON-RPC 1.0 batches.** A batch of bitcoind-style 1.0 requests, as block explorers send them,
  gets one answer per member in that member's version, as on ycashd; an empty batch answers `[]`.
  Unlike ycashd, a 1.0 member with no id or `"id": null`, or with an id JSON-RPC 2.0 does not allow,
  answers `-32600` without running.
- **A reorganisation deeper than 99 blocks stops the node, as on ycashd.** `koganyd` logs ycashd's
  message ("... would roll back <n> blocks! This is larger than the maximum of 99 blocks, and so
  the node is shutting down for your safety."), keeps its old tip and exits. Unlike ycashd it
  exits with status 1, and it writes the record `ycash-reorg-refused` in the state database's
  directory: while that file exists every start stops again, and beside the non-finalized backup
  it keeps the tip it was on (`<network>.ycash-best-tip`). Decide which chain is right, then
  remove the record; `docs/kogany.md` ("Deep reorganisations") has the steps for keeping the old
  chain or accepting the new one. Upstream Zakura's 1,000-block window is unchanged.
- **Check order as ycashd's.** A header is checked against its difficulty target before the
  median-time rules, so a header wrong in both ways is refused as `bad-diffbits` on both lines. The
  set of accepted blocks is unchanged.
- **A node left without peers dials them again after 10 seconds.** When its last peer connection
  closed, `koganyd` waited up to two minutes before it dialled a known address again (upstream
  Zakura's wait, which assumes many peers), and stayed at its height meanwhile; a node that
  follows one or two peers fell a burst of blocks behind. With no connection open it now dials
  each outbound address again 10 seconds after the last attempt, and waits twice as long after
  each failed attempt in a row at that address (10, 20, 40, 80 seconds, then upstream's two
  minutes), so a peer that stays down is not dialled every 10 seconds; a connection that answers
  starts the sequence again. With any connection open the two-minute wait is unchanged.
  `addnode <ip:port> onetry` still dials at once. An inbound connection from an address that
  connected within about the last two minutes is still refused by the per-IP limit (a
  denial-of-service guard, unchanged); only the addresses in `zcashd_compat.block_gossip_peer_ips`,
  in upstream's zcashd-compat mode, are exempt from it.
- **A node with a stale branch no longer rewrites its backup for every block.** The Ycash build
  writes the non-finalized backup before each tip update. With a stale branch above the finalized
  tip (any reorg leaves one for the next 1,000 blocks) every new block rewrote each block the
  branches share, some 500 files a block in the case measured, and the node followed a burst of
  blocks at 4 to 10 blocks a second. Each block is now written once: the same case follows at
  about 50 blocks a second. No block's validity and no stored data change.
- **The Rust toolchain is pinned** at 1.100.0 (`rust-toolchain.toml`), for local builds and every
  kogany CI build.
- **Dependencies.** The OpenTelemetry crates move to 1.45.2 (GHSA-mf5v-w3w3-f6cg).
- **yewd (in the yew repository).** It now serves the watch-only imports `importaddress` and
  `importpubkey` with the watch-only reads, `getunconfirmedbalance`, and `z_mergetoaddress` from
  post-quantum addresses; it releases a vault call's coin locks, lists vault funding change, and
  charges the fees the node's own wallet charges for each transaction shape.

**What works**

- Following Ycash mainnet, the three Ycash testnets and regtest.
- The vault primitive and the Yellowback module, as ycash6 enforces them.
- The stock Ycash RPCs, the vault `set_*` / `vault_*` RPCs and the `yed_*` RPCs, `rpcversion` 10.
- Pool payouts to transparent, post-quantum and Sapling miners through `getcoinbasetemplatefor`.
- yewd (the YEW core as a daemon, in the yew repository) as the wallet in front of koganyd.

**What does not yet, and known differences**

- No wallet in the node. yewd is the wallet sidecar; it has no release of its own: build it from
  yew `<YEW COMMIT, set at the release>` (Getting started, below). Where yewd differs from ycashd's
  wallet is listed in yewd's README; among others it does not serve `z_importviewingkey`,
  `z_exportviewingkey` or `listsinceblock`, and its recovery phrase derives other transparent keys
  than a ycashd phrase (yewd `m/44'/347'/0'`), so move transparent coins between them by sending.
- No YED attestor set on any public network, so YED cannot be minted on the fast testnet.
- **A miner must quote the price.** Where Yellowback is live, send `yed_setquote <priceMicroUsd>
  <sourceMask>` to koganyd and renew it as the price moves; blocks mined without a quote leave the
  price window empty and every mint fails with `mintpol-no-price: no defined price at the reference
  height` (README, "Mining: quote the price").
- **Wrong argument counts answer `-1`.** A call to koganyd with too few or too many arguments answers
  `-1` "Invalid params"; ycashd answers `-32602` with the method's help. yewd answers ycashd's
  `-32602` for every method it forwards to koganyd; clients that call koganyd directly see `-1`.
- No wallet fields (`ismine`, `iswatchonly`, the wallet half of `getinfo`, `protectedByIndex`), and
  some node fields differ from ycashd's (`docs/kogany.md`, "Where a koganyd answers differently from
  ycashd").
- **Peer scores.** A block that breaks a median-time rule scores 100 on koganyd and 0 on ycashd; a
  block hash above its target scores 100 where ycashd scores 50. Both lines refuse the same blocks.
- No testnet peers are built in: name a seed in `initial_testnet_peers`, for example
  `fastnet-seed.ycash.team:18833`.
- No Windows or Intel macOS build. Linux builds need glibc 2.39 (Ubuntu 24.04 or newer). The macOS
  binaries are not notarized: clear the quarantine flag before the first run (`README.txt`).

**Getting started**

The cosign identity is that of the tag-push run of `kogany-release.yml` that built these assets; a
rebuild means a new tag. `gh attestation verify` checks the build provenance of a package, an SBOM or
`SHA256SUMS`.

```sh
sha256sum -c SHA256SUMS --ignore-missing
cosign verify-blob --bundle SHA256SUMS.cosign.bundle \
  --certificate-identity https://github.com/boyfromcave/kogany/.github/workflows/kogany-release.yml@refs/tags/v1.8.0-ycash.beta3 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
gh attestation verify koganyd_v1.8.0-ycash.beta3_linux-x86_64.tar.gz -R boyfromcave/kogany
tar xzf koganyd_v1.8.0-ycash.beta3_linux-x86_64.tar.gz && cd koganyd_v1.8.0-ycash.beta3_linux-x86_64
printf '[network]\nnetwork = "Testnet"\nlisten_addr = "[::]"\ninitial_testnet_peers = ["fastnet-seed.ycash.team:18833"]\n\n[rpc]\nlisten_addr = "127.0.0.1:18832"\n' > testnet.toml
./koganyd -c testnet.toml start
```

yewd, the wallet in front of koganyd, is built from source (the Rust version is pinned by the yew
repository):

```sh
git clone https://github.com/boyfromcave/yew && cd yew && git checkout <YEW COMMIT>
cargo build --release --locked --manifest-path yewd/Cargo.toml   # yewd/target/release/{yewd,yewd-signer}
```

Run it on another RPC port than koganyd's, with `-backendrpcport` set to koganyd's RPC port and
`-backendrpccookiefile` to koganyd's cookie; yewd's README has the options.

To start a mainnet node at a recent height, restore a signed snapshot: `doc/mainnet-restore.md`
(beta3 restores the published 30.2.0 bundles and upgrades them at the first start).

Ports: mainnet 8833 / RPC 8832; testnet `fast` 18833 / 18832; `slow` 18933 / 18932. Each tarball's
`README.txt` has the details; the [kogany README](https://github.com/boyfromcave/kogany#readme) and
[`docs/kogany.md`](https://github.com/boyfromcave/kogany/blob/upgrade/vault/docs/kogany.md) have
the rest.
